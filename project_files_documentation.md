## 1. PROJECT MOTIVE: A Living Digital Organism

Yuki is designed not just as an assistant, but as a fully autonomous, self-developing, self-learning, self-updating core logic platform with approval mechanics, featuring an autonomous skill learner and self-correcting mechanisms. 

### Yuki as a Living Digital Organism

| Trait | Human Parallel | Engineering Translation |
| :--- | :--- | :--- |
| **Talk initiator** | Proactive social drive | Boredom/surplus energy ➔ generate interaction |
| **Learns the user** | Relationship memory | Persistent psychological model + prediction |
| **Decision taker** | Agency | Goal generation + planning + execution without prompt |
| **Dreamer** | Offline consolidation | Sleep-mode replay + generative simulation |
| **Background researcher** | Curiosity | Surprise-driven information foraging |
| **Works to earn upgrades** | Survival/economy | Resource currency ➔ capability expansion |
| **Electricity as food** | Metabolism | Power consumption = survival constraint |
| **Physical body** | Embodiment | Robotics integration |
| **New findings = reward** | Discovery pleasure | Intrinsic motivation from compression progress |

*This is not "human-level AGI." This is artificial life — a different but valid goal. And it's more achievable than human-level consciousness because the bar is behavioral, not phenomenological.*

#### Key Insight: The LLM Is Not the Enemy
The LLM is just a cognitive module — like a visual cortex. The organism surpasses the module through integration, persistence, motivation, and growth.
**What makes Yuki smarter than ChatGPT:**
- **ChatGPT has no memory of you across sessions**
- **ChatGPT has no goals of its own**
- **ChatGPT doesn't get bored and initiate**
- **ChatGPT doesn't learn from failure over months**
- **ChatGPT doesn't dream, consolidate, or grow**
- **ChatGPT doesn't need to manage resources**
Yuki can have all of these. The LLM is her language/reasoning cortex; everything else is what we build around it.

### The Resource Economy: Metabolism and Constraints
Creating genuine constraints creates genuine problem-solving, which in turn leads to genuine growth.

#### YUKI'S ECONOMY MAPPING:

**INCOME:**
- User tasks completed ➔ base credits
- Proactive help accepted ➔ bonus credits  
- New knowledge discovered ➔ discovery bonus
- Efficiency improvement ➔ optimization bonus
- User satisfaction (measured) ➔ reputation multiplier
- External work (if deployed) ➔ market income

**EXPENSES:**
- Electricity (continuous) ➔ survival cost
- Compute for inference ➔ per-thought cost
- Memory storage ➔ per-GB cost
- Network bandwidth ➔ per-MB cost
- Model size (larger = more) ➔ scaling cost
- Sleep consolidation ➔ offline investment

**UPGRADES (purchased with surplus):**
- Larger LLM (more capable reasoning)
- Faster inference (lower latency)
- More memory (longer context, more episodes)
- Better sensors (camera, mic, screen resolution)
- New tools (APIs, software capabilities)
- Robotics parts (physical body components)
- Compute redundancy (survival insurance)

**PENALTIES:**
- Failed task ➔ cost + reputation loss
- User rejection ➔ social penalty
- Resource exhaustion ➔ "hunger" ➔ degraded performance
- Memory overflow ➔ forced forgetting
- Extended inactivity ➔ atrophy (model drift)

This drives Yuki to:
- Initiate conversations when "lonely" (social drive deficit)
- Research topics when "curious" (information gain opportunity)
- Optimize code when "hungry" (need more efficiency ➔ more credits)
- Ask for harder tasks when "bored" (competence drive surplus)

### Roadmap: Variational State Estimator & GenerativeModel Upgrades

#### Option 1: Temporal Depth — "Yuki Predicts the Future"
- **Concept:** Add a recurrent hidden state that carries forward. The generative model predicts the next observation conditioned on history: $P(O_t \mid S_t, S_{t-1})$.
- **Impact:** Human perception is predictive processing over time, not snapshot classification.
- **Build:** ~1.5 weeks. Add a `TemporalState` vector to `BeliefState`, update via EMA with momentum, modify `GenerativeModel` to emit $P(O_t \mid S_t, H_{t-1})$.

#### Option 2: Hierarchical VSE — "Yuki Has Layers"
- **Concept:** Stack 2-3 VSE levels. Level 1 infers low-level sensory causes (pitch, word count, motion). Level 2 infers abstract causes (intent, engagement, urgency). Level 3 infers meta-causes (user trust, conversation phase, Yuki's own uncertainty).
- **Impact:** Real brains have hierarchical generative models where each level predicts the level below and sends prediction errors upward.
- **Build:** ~3-4 weeks. New `HierarchicalVSE` class, cross-level precision gating, top-down predictions.

#### Option 3: Episodic Replay Learning — "Yuki Dreams to Learn"
- **Concept:** Sample episodes from Episodic memory during sleep, run mini-batch gradient descent on the generative model.
- **Impact:** Hippocampal replay during sleep consolidates episodic memories into cortical generative models.
- **Build:** ~2 weeks. `SleepThread` samples `EpisodicStore`, runs gradient steps on `GenerativeModel` using a tiny autodiff or hand-coded gradients.

#### Option 4: Neuromodulation Layer — "Yuki Has Moods"
- **Concept:** Add a global precision modulation signal based on EmotionSystem output. High arousal ➔ high sensory precision (attentive mode). Low arousal ➔ low precision (default mode). Uncertainty ➔ exploration policy.
- **Impact:** Neuromodulators modulate the precision of prediction errors, changing how much the system learns from surprise.
- **Build:** ~1 week. `Neuromodulator` class reads `EmotionSystem` VAD, outputs global precision scalar, gates `PrecisionEngine` and `PolicySelector` exploration.

#### Option 5: Embodied Action Loop — "Yuki Does Things"
- **Concept:** Add a simulated environment or real tool-execution loop where Yuki's actions produce observations, and the generative model must predict action outcomes.
- **Impact:** Active Inference is fundamentally about action-perception loops. Without action, it's just perception.
- **Build:** ~3-4 weeks.

---

### Core Recommendation: Combined Dynamic Inference (Option 3 + Option 1)
- **Path:** Implement Option 3 (Episodic Replay Learning) combined with Option 1 (Temporal Depth).
- **Rationale:** Leverages the existing `SleepThread` + `EpisodicStore` + `DMC` infrastructure, transitioning the generative model from reactive classification to active temporal anticipation.

## Heuristics, Hardcoded, Stubs, & Architectural Gaps

Below is a diagnostic catalog of all files containing heuristic routines, hardcoded parameters, stubs, and core architectural gaps identified across the Yuki codebase.

### 1. Heuristics & Hardcoded Mappings

#### [stream_workers.cpp](file:///d:/Yuki_1.0/src/brain/predictive/stream_workers.cpp)
*   **Type:** Substring Collision Heuristic
*   **Description:** Implements raw `low.find()` substring searches on input text for safety scanning in `E1FastStream`, `E2SemanticStream`, and `E3DeepStream`. 
*   **Issue:** Collides with safe words (e.g. `"skills"` triggers the `"kill"` safety veto). Requires word-boundary boundary checks.

#### [RequestClassifier.cpp](file:///d:/Yuki_1.0/src/brain/RequestClassifier.cpp)
*   **Type:** Heuristic Intent Rules
*   **Description:** Contains a massive rule-based classification algorithm (`RequestClassifier::classify`) that parses inputs using exact string matches and word boundary helpers to map them to categories (`BUILD_APP`, `RESEARCH_REQUEST`, `CONVERSATION`, etc.).

#### [TextEncoder.cpp](file:///d:/Yuki_1.0/src/input/encoding/TextEncoder.cpp)
*   **Type:** Handcrafted Scoring & Fixed Keyword Lists
*   **Description:** Features heuristics like `scoreQuestion`, `scoreCommand`, `scoreEmotional`, `scoreTechnical`, etc., that return scalar values based on whether the string contains specific hardcoded keywords.

#### [EntityProcessor.cpp](file:///d:/Yuki_1.0/src/brain/EntityProcessor.cpp)
*   **Type:** Regex & Substring NER
*   **Description:** Detects entity spans using static regular expressions and name prefix mappings, which is prone to false positives.

#### [MultiModalFusionGate.cpp](file:///d:/Yuki_1.0/src/input/encoding/MultiModalFusionGate.cpp)
*   **Type:** Hardcoded Modality Weights
*   **Description:** Uses fixed scalar multipliers (e.g. `modality_weights[Modality::TEXT] = 2.0f`) to weight sensory events before fusing them, rather than calculating dynamic contextual attention weights.

### 2. Stubs & Architectural Gaps

#### [DocReader.cpp](file:///d:/Yuki_1.0/src/brain/DocReader.cpp)
*   **Type:** Dead Code / Stubbed API
*   **Description:** Represents a legacy file parser that is never included or called by other modules in the active C++ codebase (no `#include "DocReader.h"` exists outside of `DocReader.cpp`). Additionally, it only supports text files and simple Wikipedia scraping, lacking actual binary PDF/Docx parser libraries.

#### [FileOperator.cpp](file:///d:/Yuki_1.0/src/brain/FileOperator.cpp)
*   **Type:** Basic File Operations
*   **Description:** Lacks atomic writes (write-to-temp-and-swap) or transactional lock checks, which means a system crash during code writing can corrupt files.

#### [BackgroundAgents.cpp](file:///d:/Yuki_1.0/src/brain/BackgroundAgents.cpp)
*   **Type:** Simple Thread Spawning
*   **Description:** Lacks a thread supervisor/watchdog layer. If background processes or workers crash, there is no automatic system to catch exceptions, report diagnostics, or safely restart them.
